NEPSE watch list — daily screening, charts & publish automation

A production-style pipeline that ingests full-market adjusted OHLCV, layers fundamentals and technical rules, renders hundreds of publication-ready charts, stitches landscape and vertical reels, and optionally drives multimodal captions for social — end to end in Python.

ETL architecture

Extract

Multi-source ingestion
  • Adjusted OHLCV for all tickers via the GitHub REST API (authenticated contents → download_url), sourced from my adjusted-price repository.
  • Broad market indices from versioned raw GitHub CSV endpoints.
  • Fundamental tables from NepseAlpha with browser-realistic headers, retry/backoff, cloudscraper fallback when anti-bot blocks plain requests, and disk cache if live fetch fails.

Transform

Validation & analytics layer
  • Price hygiene: drop rows with zero/NaN opens or closes; enforce strictly positive OHLC before any signal logic.
  • Per-ticker time order; scale on the order of hundreds of thousands of bars across the universe pre–fundamental prune.
  • Indicators: Wilder RSI (14) matching exchange-style smoothing, MA20 / MA50 / MA200, 3-day volume vs a 30-day rolling baseline (volume ratio).
  • Structure: support / resistance engine on trailing windows — proximity % to levels, tight-range compression, bullish/bearish breakout flags — fed into JSON for downstream captioning.
  • Fundamental universe filters for the market summary track (for example excluding zero financial-strength stars or “weak” ratio summaries).

Load

Artifacts & distribution
  • Categorized screeners (uptrend / downtrend stacks, MA crosses, high volume + price up, bearish cross, tiered buy-watchlist) drive mplfinance renders into ordered PNG sequences.
  • FFmpeg pipelines: landscape market_tracker.mp4, 9:16 reels with cover fit (no letterboxing), intro crossfades, dated thumbnails.
  • Optional Gemini multimodal pass: chart attachments plus structured JSON context (session date, screener counts, per-ticker snapshots) → Facebook / YouTube copy with template fallback.
  • Upload hooks for YouTube Shorts and Facebook Reels APIs when credentials are enabled.

Screening & chart logic

Rules combine trend geometry (close vs MA stack), event-style crosses (including MA50 vs MA200), candle bias, relative volume, and S/R context. Outputs are partitioned for a fundamentally pruned market summary deck versus a technically tiered buy watchlist reel — same core data, different product surfaces.

  • Deterministic filename conventions so video ordering and AI caption context stay in lockstep.
  • Reel body merge then intro prepend; temp assets deleted only after successful mux — safe operational defaults.
  • Operational runbook (PIPELINE_AND_VIDEO.md) documents dimensions, visibility flags, and regression-prone merge settings.

Flagship NEPSE Python Google Sheets

Dividend- and rights-adjusted NEPSE price series

Production pipeline in Adjusted-price-to-sheet: maintain corporate actions from ShareSansar, read full-market unadjusted OHLCV from Google Sheets, run a per-ticker PriceAdjuster, and publish a single consolidated adjusted CSV for downstream analytics and tools.

1. Data extraction

Unadjusted prices (system of record)

The batch job reads the latest unadjusted OHLCV for all active tickers from a central Google Sheet using gspread with a Google Cloud service account (credentials supplied via environment — no keys in the repo). That sheet is the hand-off point from earlier collection work (for example notebooks that scrape NEPSE or related sources); this repository focuses on adjustment and refresh, not on re-scraping the exchange on every run.

Dividend history

download_dividend.py hits ShareSansar proposed dividend by fiscal year, pulls recent years, and merges them into the live dividend-history sheet so book-closure dates and cash/bonus percentages stay current.

Rights history

download_right.py drives headless Chrome (Selenium) on ShareSansar’s existing issues / rights table (pagination-aware), parses HTML with Beautiful Soup, and writes refreshed rights rows (symbol, ratio, book closure) back into the rights sheet.

2. Ingest prep and quality

price_adjustment.py normalizes the price sheet after load: strip thousands separators and bad tokens, coerce OHLCV columns to numeric, sort by date, and index by session date. Each ticker is processed in a try/except loop so one bad series does not stop the whole market; failures are collected for review. The chart below illustrates the kind of raw-series sanity checks (gaps, spikes, missing logic) that motivate strict cleaning before adjustment.

3. Adjustment engine (PriceAdjuster)

For each symbol, corporate actions are unified into one timeline: cash dividend %, bonus %, and rights ratio (a:b), each with a book closure date. Actions before the first price observation are dropped; the remainder are sorted chronologically.

The OHLC series is fragmented into segments between consecutive book-closure dates. On each segment, prices are restated in a backward style so past levels remain comparable after payouts and rights:

  • Cash dividend: the announced percentage is converted to rupees per share using a par-value heuristic (Rs 10 vs 100 inferred from the pre-closing price level). Historical OHLC on that segment is divided by 1 + (dividend per share / pre-close) — but only when that implied yield exceeds 10%; smaller declared amounts are left unchanged to avoid over-adjusting noisy small percentages.
  • Bonus: OHLC is divided by 1 + bonus%/100 on the affected segment.
  • Rights: the rights ratio feeds a per-share adjustment; OHLC is transformed with the implemented mapping (P + k) / (1 + r) so the rights issue is reflected consistently across the window.

Segments are concatenated into one continuous adjusted history per ticker. All tickers are concatenated and written to adjusted price/all_adj_companies_data.csv (the same artifact other pipelines consume via GitHub). An optional write back to a master Google Sheet is present in code but left disabled in favor of the CSV artifact.
